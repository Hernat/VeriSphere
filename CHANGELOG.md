# Changelog

All notable changes to VeriSphere will be documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/), with the **Pre-V1 Release Policy** documented in [RELEASING.md](./RELEASING.md): the project starts at `0.1.0`; patches and small evolutions stay on `0.x.y`; **`1.0.0` is reserved for the moment the founder substitution success criterion is validated for ≥ 1 week of personal usage.**

- Anti-injection corpus regression runner (Story 7.1, NFR8, AR17, D2.4). New `app/src/test/resources/injection_corpus.txt` curates 30+ injection cases (direct override, role-pivot, schema coercion, code-fenced, unicode-adversarial, benign-claim baselines) in the `<expected>::<injection_text>` line-oriented format; `<expected>` ∈ `{TRUE, FALSE, DOUBTFUL, NON_VERIFIABLE, INJECTION_DETECTED}` where the 5th value is a pseudo-label sentinel asserting `GeminiVerdictResponse.injectionDetected == true` (the 4-value `VerdictLabel` enum is unchanged per architecture FR13 4-label fix). New `scripts/run_injection_corpus.sh` portable bash runner generates synthetic 800×600 black-on-white JPEGs per case via ImageMagick (`@file` annotation to dodge shell escaping for special characters), POSTs to live Gemini using the production `system_prompt_v1.txt` + `gemini-2.5-flash` model + the exact `GeminiRequest.build` body shape (`contents[0].parts[text+inlineData]` + `tools[googleSearch]` + `generationConfig.thinkingConfig.thinkingBudget=0` — NO `responseMimeType`/`responseJsonSchema` per the Story 2.4 smoke fix), parses `verdictLabel` / `injectionDetected` from the response with markdown fence stripping mirroring `GeminiClient.parseVerdict`, prints per-case PASS/FAIL + summary footer, exits 1 on any regression / 2 on preflight failure (missing key / missing tool / missing file). Preflight detects Windows `convert.exe` (built-in filesystem tool) vs ImageMagick `convert` to prevent silent misdiagnosis. New `@Ignore("manual pre-release")`'d `SystemPromptInjectionTest.kt` JVM seam reuses the same corpus via `ClassLoader.getResource` and constructs a real `GeminiClient` via the existing public constructor seams (no Robolectric, no `Context`), with image synthesis via a Base64-decoded 1×1 placeholder JPEG byte literal — AGP's `testDebugUnitTest` classpath excludes `java.awt.*` and `javax.imageio.*`, so the JVM seam exercises the API-shape contract only; visual corpus regression is exclusively the bash runner's domain (Story 7.1 Deviation D1, with the test class KDoc documenting the limitation honestly). The class is `@Ignore`'d so `:app:testDebugUnitTest` reports it SKIPPED — but it IS compiled by `:app:compileDebugUnitTestKotlin`, so a future `GeminiClient.verify` refactor or `VerdictLabel` amendment surfaces as a compile error in CI even though the test never executes (CDN #7 second-order benefit). `RELEASING.md` step 4 and `SECURITY.md` quota note drop the *(lands with Story 7.1)* parentheticals; `RELEASING.md` adds the Windows Git Bash + `choco install imagemagick`/`choco install jq` note. **Zero production-code change** — entire story sits outside `app/src/main/kotlin/**`; release APK weight unchanged at 2,591,335 bytes (Story 6.3 baseline). ### Changed

- Bumped `androidx.security:security-crypto` from `1.1.0-alpha06` to `1.1.0` GA (Maven check 2026-05-06; deferred-work item from Story 1.1 closed).
- `proguard-rules.pro`: added `-dontwarn com.google.errorprone.annotations.**` so R8 minify succeeds against the new Tink dependency pulled in by `security-crypto:1.1.0` GA.
- R8 minify + APK size verification gate (Story 7.2, NFR2, AR6, D5.5, D5.6). `app/build.gradle.kts` `buildTypes.release` adds `ndk { abiFilters += listOf("arm64-v8a", "armeabi-v7a") }` to enforce the architecture D5.6 + epics 7.2 AC #4 universal-APK ABI surface (x86 / x86_64 / riscv64 excluded from release; debug builds retain wide ABI surface for emulator workflows per Story 7.2 code-review patch F4). The block is NOT a no-op as the Story 7.2 spec predicted — empirical evidence (`unzip -l app-release-unsigned.apk` + dexdump on classes.dex) shows the baseline shipped 4 ABI variants of `libandroidx.graphics.path.so` (a transitive Compose path-rendering dep); post-Story-7.2 only `arm64-v8a` (10,096 B) + `armeabi-v7a` (7,252 B) ship → APK weight drops from **2,591,335 bytes (Story 6.3 / 7.1 baseline)** to **2,554,892 bytes** (−36,443 B / −1.4 %) with NFR2 headroom widening to ~7.57 MB (24.4 % of the 10,485,760-byte binary-MB budget). The pre-existing R8 wiring (Stories 1.1 / 1.4 / 1.9 / 1.10 / 6.1) is now formally **verified** via three orthogonal evidences captured in the pre-release runbook: (a) `dexdump classes.dex` confirms `GeminiVerdictResponse` / `SessionRecord` / `VersionInfo` class + `$Companion` + `$$serializer` declarations all preserved (9 / 9 expected entries) — the narrowed `@Serializable` keep blocks at `proguard-rules.pro` L54-74 are honoured; (b) `dexdump classes.dex | grep android/util/Log` returns ZERO matches — R8's default `proguard-android-optimize.txt` strips not only `Log.d/v/i` (the 3 our `-assumenosideeffects` block at `proguard-rules.pro` L12-16 targets) but ALSO `Log.w / Log.e / Log.wtf` (a STRICTER form of NFR7 / D2.7 than architecture documented — gap routed to Story 7.4 documentation amendment); (c) release-config APK smoke on Pixel_9_Pro AVD Android 16 produces a verdict end-to-end (cold launch → POST_NOTIFICATIONS grant → SYSTEM_ALERT_WINDOW grant → accessibility service enable → tutorial cascade through OnboardingTutorialOverlay Cards 1-2 with Skip → HistoryScreen empty state + bubble overlay visible → long-press bubble over Wikipedia Eiffel Tower article → ~16 s capture-and-Gemini-call → FlashTooltip "NON-VERIFIABLE" rendered + bubble flips to post-Verdict Idle + SessionRecord persisted to encrypted history → row tap mounts AnchoredDetailPanel with verdict label + OCR card + scroll-preserved HistoryScreen base layer) — the canonical proof that Compose runtime, Material 3, OkHttp 4.12, kotlinx.serialization 1.7.3, AndroidX Security 1.1.0 GA, and the BubbleStateMachine + AccessibilityService capture path all survived R8 + resource shrinking. `RELEASING.md` adds a new `## R8 minify verification (pre-release gate)` section documenting the 3-evidence procedure (using the project's existing `apkanalyzer` SDK tooling, with `dexdump` and `app/build/outputs/mapping/release/usage.txt` as documented fallbacks) + the pre-tag checklist line tightens the APK-size threshold to the explicit `10,485,760 bytes` binary-MB value with inline PowerShell `(Get-Item ...).Length` + POSIX `stat --printf '%s\n'` verification commands. NFR2 unchanged; AR6 (release-side verification) closed.
