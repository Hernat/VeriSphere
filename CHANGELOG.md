# Changelog

All notable changes to VeriSphere will be documented in this file.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/), with the **Pre-V1 Release Policy** documented in [RELEASING.md](./RELEASING.md): the project starts at `0.1.0`; patches and small evolutions stay on `0.x.y`; **`1.0.0` is reserved for the moment the founder substitution success criterion is validated for ≥ 1 week of personal usage.**

## [0.2.2] — 2026-05-30

### Fixed

- **Gemini API-key validation rejected valid keys** (`ApiKeyValidator.validateGeminiKey`). The Story 10.1 gate required the key to start with `AIza` **and** be exactly 39 chars (code-review D2, 2026-05-20). Field report (2026-05-30): the `AIza` prefix is not present on every Gemini key, so the prefix gate — and the equally-brittle exact-39 length gate — blocked valid keys with a hard `Format invalide` error and no way past it. The format gate is now **removed entirely**: `validateGeminiKey` returns `Valid` for any non-blank normalized result and `Empty` otherwise, identical to the SerpAPI contract in the same file (neither service publishes a stable key format we can rely on locally; a wrong key surfaces server-side rather than being blocked). Removed the `GeminiKeyValidation.InvalidFormat` state, the `GEMINI_PREFIX` + `GEMINI_MIN_LENGTH` constants (and their pin tests), the now-dead `settings_gemini_key_invalid` string, and the `InvalidFormat` branch in `SettingsScreen.geminiErrorMessageFor`. `normalizeApiKey` (whitespace + Unicode-invisible stripping) is unchanged — the stored key stays byte-identical to what the user pasted. UI: `settings_gemini_key_hint` `AIza…` → `Colle ta clé ici`. `ApiKeyValidatorTest` rewritten — prefix / numeric / short keys now assert `Valid`, and the Unicode-invisible cases assert `normalizeApiKey` directly (validation alone no longer distinguishes a stripped key); `SettingsViewModelTest` InvalidFormat-abort case re-cast as a short-key-persists case.

### Fixed

- Live-runtime regression : `AgreementScorer.toBoundaryRegex` previously emitted `(?Ui)\b\Q…\E` patterns — JVM's `java.util.regex` accepts the `(?U)` UNICODE_CHARACTER_CLASS flag but Android's ICU regex engine rejects it at class-load with `PatternSyntaxException`, taking the bubble service down on the first SerpAPI enrichment. Patch drops `(?U)` and relies on `RegexOption.IGNORE_CASE` ; `\b` boundary is now ASCII-only (same as pre-Epic-9). JVM unit tests are NOT sufficient to catch this class of Android-specific regex divergence ; an Android-side smoke or Robolectric class-load probe is the right test surface (recorded as HOTFIX-1 in `_bmad-output/implementation-artifacts/deferred-work.md`).

- 42 code-review patches across two adversarial-review passes (Group A SerpAPI + Group B UI/Theme), covering : production wiring of the SerpAPI lambdas into `BubbleOverlayService.CapturePipeline` (was dark code in `main`) ; `SerpApiClient` 15s `callTimeout` enforced via a derived OkHttp client ; new `SerpOutcome.Failure.EmptyQuery` / `EmptyPayload` variants to disambiguate semantics ; `AgreementScorer` keyword-overlap dedup (`confirmé` / `confirmée` no longer double-count `confirmées`) ; `hl=fr` / `gl=fr` SerpAPI locale params ; `VerdictHeadline` U+2019 curly-apostrophe variants ; deleted dead `GeminiClient.stripVerdictPrefixDeprecated` + `VERDICT_PREFIXES` companion ; `SerpQuotaGate` atomic-CAS on the clock-skew branch + forward-skew upper-bound clamp ; `SessionRecord` cap at 6 SerpReferences + 2000-char markdown to bound encrypted-SharedPrefs growth ; `mapGoogle` `joinToString(". ### Changed

- **Palette darkening for strict WCAG AA body contrast.** `vs_ink_soft` light : `#9C9588` → `#757066` (2.76:1 → 4.64:1 on paper). `vs_ink_soft` dark : `#7C7568` → `#908A7E` (3.85:1 → 5.14:1). `vs_accent_sage_deep` light : `#4E7B5E` → `#44704F` (4.46:1 → 5.19:1 on canvas — was just under the 4.5:1 AA-body floor). Dark-mode `accent_sage_deep` unchanged (`#7BA889` was already at ~7.8:1 on dark canvas).

- `VeriSphereTypography` reverted from `val ... get() = Typography(...)` (recomputed per-recomposition) to a single eager `val Typography(...)` (one allocation per process lifetime). The `get()` form had been silently churning typography across every `VeriSphereTheme` recomposition.

- `CapturePipeline.CAPTURE_TIMEOUT` : 60 s → 80 s to fit the Gemini 60 s ceiling + SerpAPI 15 s budget + 5 s structural slack. Without this bump, a 55-second Gemini success followed by a 15-second SerpAPI call would trip the outer `withTimeout` and discard the verdict.

- `DOUBTFUL` verdict glyph in `HistoryItemRow` : `?` → `⁇` (U+2047). The single question mark was visually indistinguishable from regular punctuation in headlines.

- `HistoryScreen` subtitle no longer claims a "· 24 h" rolling window (the rendering site has no such filter ; the suffix was misleading) and now uses `R.plurals.history_screen_subtitle` for grammatical agreement with `records.size`.

- File rename : `wisper flow .md` → `wispr-flow.md` (correct spelling + no whitespace + no trailing space).
